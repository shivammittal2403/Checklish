How do NTBS and LLMNR work?

Row 4
Sno
2
Key Notes
1. These two protocols have been implemented by Windows. LLMNR is the successor to NetBIOS, but for reasons of backward compatibility, both have been enabled by default since Windows Vista. 2. Their purpose is to supplement the DNS protocol when it fails to resolve an address. The big difference is that their queries are not sent to a specific server (DNS server) but are broadcast over the subnet. This enables automatic discovery but also allows any machine on the subnet to respond to these requests.

How to prevent NTLM Relay Attacks?

010

To prevent NTLM relay attacks, it is possible to counter each of the methods used to obtain a NET-NTLM hash:

Sno
1
Key Notes
1. Disable LLMNR/NETBIOS protocol(s), 2. Disable all Microsoft services vulnerable to coerced attacks, 3. Set up a static ARP table, etc.
011

The most effective way of countering the relay is to implement these actions on the servers.

1. Disable NTLM authentication on your network and delegate it solely to Kerberos if possible. 2. Enable signing on SMB and LDAP. 3. The HTTPS protocol does not support signing. You can therefore disable the NTLM protocol for HTTPS services specifically, or you can use EPA (Extended Protection Authentication) protection. In short, this protection adds a signature to protocols that are not implemented.
